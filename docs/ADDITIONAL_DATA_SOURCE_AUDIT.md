# 추가 발전소 데이터 후보 및 편입 기준

검증일: 2026-08-27 (Asia/Seoul)

추가 발전소도 기존 발전소와 **동일한 모델 입력 컬럼**을 사용합니다. 파일마다 원본 컬럼은 달라도
수집 adapter가 공통 발전량 계약으로 변환하며, 공통 피처 중 관측할 수 없는 값은 컬럼을 삭제하지
않고 `NaN`과 동일 위치의 결측 정보로 표현합니다. 발전소별로 서로 다른 피처 목록을 만드는 방식은
사용하지 않습니다.

## 편입 게이트

발전소를 학습 테이블에 넣기 전에 아래 조건을 모두 검사합니다.

| 구분 | 기본 기준 | 이유 |
|---|---:|---|
| 발전소 식별 | 물리 설비를 가리키는 안정적인 `plant_id` | 서로 다른 설비를 한 시계열로 합치는 오류 방지 |
| 기간 | 최소 3년, 권장 4년 이상 | 계절성을 포함한 시간순 Train/Validation/Calibration/Test 확보 |
| 시간 커버리지 | 95% 이상 | 대량 보간으로 만들어진 가짜 패턴 방지 |
| 최대 연속 공백 | 24시간 이하를 기본 심사선으로 사용 | 장기 정지·수집 중단 구간을 정상 시계열로 오인하지 않기 위함 |
| 설비 정보 | 용량과 발전원 필수 | 물리 범위와 capacity factor 검증 |
| 기상 결합 | 좌표 또는 사람이 검토한 KMA 관측소 매핑 | 잘못된 지역 기상을 붙이는 누수·오류 방지 |
| 단위 | 단위와 시간 간격 의미 확정 | kW, kWh, MWh 혼합으로 생기는 1,000배 오류 방지 |
| 평가 | 공통 전역 시간분할 + 발전소 그룹 holdout | 기존 발전소 미래와 신규 발전소 일반화를 따로 평가 |

이 기준은 [`config/candidate_sources.json`](../config/candidate_sources.json)에 기계 판독 가능한 형태로
보존했습니다.

## 실파일 검증: 한국농어촌공사 영암

[공공데이터포털 공식 데이터](https://www.data.go.kr/dataset/15005796/fileData.do?lang=ko)의
최신 파일과 주기성 과거 파일 2020~2025를 내려받았습니다. 원본은
`file/raw/한국농어촌공사/영암/`에 보관하고 Git에는 포함하지 않습니다.

| 연도 | 원본 일행 | 식별 가능한 발전소 | 판정 |
|---:|---:|---:|---|
| 2020 | 366 | 없음 | 격리: `시설명` 없음 |
| 2021 | 365 | 없음 | 격리: `시설명` 없음 |
| 2022 | 1,095 | 영암1차·영암2차·율치 | 발전량 품질 게이트 대상 |
| 2023 | 1,095 | 영암1차·영암2차·율치 | 발전량 품질 게이트 대상 |
| 2024 | 1,098 | 영암1차·영암2차·율치 | 발전량 품질 게이트 대상 |
| 2025 | 1,095 | 영암1차·영암2차·율치 | 발전량 품질 게이트 대상 |

2022~2025는 날짜·발전소 중복 0건, 음수 0건이며 24개 시간값 중 결측은 1칸입니다. 매일 24시간
합계가 원본의 `계`와 일치합니다. 설비용량은 영암1차·2차 각각 1.4916MW, 율치 0.9198MW입니다.
표준 유효 행은 105,191개이며 168시간 purge를 적용한 공통 분할은 Train 63,113,
Validation 15,276, Calibration 10,014, Test 15,276행입니다. 경계는 각각
2024-05-26 13:00, 2024-12-31 17:00, 2025-05-26 19:00입니다.

포털 설명은 시간 버킷의 단위를 `kW`라고 적고 파일은 24개 버킷을 일계로 합산합니다. 1시간
평균출력의 수치는 해당 한 시간 에너지 `kWh`와 같으므로 `/1000`해 MWh로 변환했습니다. 이 해석은
일계 합 일치와 설비용량 물리 상한으로 재검증했습니다. 발전소별 최대 시간 capacity factor는
영암1차 0.9661, 영암2차 0.9785, 율치 0.9183으로 모두 1.05 이하이며 manifest의
`unit_validation.passed=true`, `unit_review_required=false`로 기록됩니다.

기상 결합은 단순 군 중심점 최근접 계산으로 자동 결정하지 않았습니다. 영암1·2차는 공식 공개
위치와 해안권을 검토해 목포 ASOS 165, 율치는 학산면 상월리 율치저수지 근거를 검토해 강진군
ASOS 259로 매핑했습니다. 결정과 근거 URL은
[`config/reviewed_weather_mappings.json`](../config/reviewed_weather_mappings.json)에 버전 관리하며,
registry에는 `weather_mapping_method=reviewed_config_mapping`으로 남습니다. 그 결과 세 발전소는
같은 26개 공통 피처 계약으로 Gold에 편입됐습니다.

재현 명령은 다음과 같습니다.

```powershell
python app.py audit-candidate-data
```

이 명령은 2020~2021을 격리하고, 2022~2025를 연도별 gzip 파티션으로 만들며, 원본·산출물
SHA-256, 발전소별 연속성, 물리 상한, 공통 4구간 분할 행 수를
`file/standardized/candidates/krc_yeongam/candidate_manifest.json`에 기록합니다.

## 이번에 추가 확보한 실파일

- [남부발전 용수리](https://www.data.go.kr/data/15095404/fileData.do): 2020-10-01~2026-02-28,
  1,977일×24시간. 공식 위치와 고산 ASOS 185 매핑을 검토해 2025년까지 Gold 편입.
- [남부발전 신풍리](https://www.data.go.kr/data/15109998/fileData.do): 2021-05-01~2026-02-28,
  1,765일×24시간. 공식 성산읍 위치와 성산 ASOS 188을 검토해 2025년까지 Gold 편입.
- [농어촌공사 진도](https://www.data.go.kr/data/15080933/fileData.do): 2019년 365개 유효 일행.
  전남 표본이라는 장점은 있으나 1년으로는 공통 4구간 평가가 불가능해 staging만 수행.

용수리·신풍리는 누적 snapshot이므로 기존 공개파일과 겹치는 시각을 더하지 않습니다. Gold
reconciliation은 동일 `timestamp + company + plant_id`에서 파일명 `YYYYMMDD`가 최신인 값을
선택하고, 날짜가 없는 파일끼리는 deterministic 입력 순서를 사용합니다.
현재 로컬 기상 연간 파일은 2025년까지이므로 2026년 발전량 2,832행·2개소는 Silver에 보존하고
Gold에서만 보류합니다.

## 한 모델에서 여러 발전소를 학습하는 방식

입력 텐서의 컬럼 수와 의미는 모든 발전소에 동일합니다. 시퀀스만 `plant_id` 경계 안에서 만들고,
공유 모델은 용량·설치각·좌표·기상·태양 위치 같은 공통 변수를 통해 설비 차이를 학습합니다.
현재 `plant_id` 자체는 시퀀스 경계에 사용되고 모델 입력에는 직접 넣지 않습니다. 학습 가능한
plant embedding은 다음 controlled ablation 후보입니다.

- 알려진 발전소의 미래 정확도: plant embedding이 도움이 될 수 있습니다.
- 새 발전소 cold-start: 용량·좌표·설치각 같은 정적 메타데이터와 `unknown plant` embedding이
  필요하며, 알려진 ID 암기에 의존하면 안 됩니다.
- 따라서 전역 시간 Test와 별도로 leave-one-plant-out/group holdout을 실행해 두 성능을 분리합니다.
- 데이터가 충분해진 뒤에만 공유 backbone + 소형 plant adapter/head의 partial pooling을 비교합니다.

결론적으로 발전소마다 피처 목록을 달리하는 것이 아니라, 공통 스키마 위에서 결측·정적 메타데이터·
선택적 임베딩으로 이질성을 표현하는 구조입니다.
