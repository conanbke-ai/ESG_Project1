# 서비스 전체 모집단과 AI 학습 모집단 분리 정책

최종 보완일: 2026-09-17 (Asia/Seoul)

## 1. 왜 두 모집단을 분리했는가

이 프로젝트는 **사용자에게 보여주는 전체 발전소 현황 데이터**와 **AI 모델 학습에 사용하는 데이터**를 같은 모집단으로 취급하지 않는다.

두 데이터의 목적이 다르기 때문이다.

- 전체 발전소 현황은 사용자가 실제 공개 설비 현황을 탐색하는 서비스 기능이다.
- AI 학습 데이터는 시계열 예측을 공정하고 재현 가능하게 수행하기 위한 실험 모집단이다.
- 따라서 어떤 발전소가 AI 학습 기준을 통과하지 못했다고 해서 전체 현황 화면에서도 삭제하면 안 된다.
- 반대로 화면에 존재하는 모든 발전소를 품질 심사 없이 그대로 모델 학습에 넣어서도 안 된다.

이 분리는 데이터 누락이 아니라 **표현용 모집단과 모델링용 모집단의 책임을 분리한 설계**다.

---

## 2. Population A — 전국 발전소 현황 / 서비스 표시 모집단

### 목적

`solar_dashboard.html`의 전국 태양광 발전설비 현황과 지역별 통계·검색에 사용한다.

### 원칙

전국 현황은 **AI 학습 적격 여부와 무관하게 공식 공개 원본 범위를 유지**한다.

현재 기준 원천은 한국전력거래소 EPSIS의 `발전원=태양에너지` 전국 설비 등록 자료다.

서비스 표시 모집단에는 다음 원칙을 적용한다.

1. 모델 학습 제외 여부를 이유로 발전소/등록행을 삭제하지 않는다.
2. 공식 원본의 등록 범위와 총량을 보존한다.
3. 중복으로 보이는 레코드도 공식 고유키가 없으면 임의 제거하지 않는다.
4. 지역명 개편·표준화는 표시/집계를 위한 정규화이며 원본 fact를 바꾸지 않는다.
5. 지역 충돌처럼 근거가 부족한 행은 `미확정 지역` 등으로 격리할 수 있지만 전체 원본 모집단에서는 제거하지 않는다.
6. 원본 SHA-256, 기준일, 행 수, 설비용량 총량을 이용해 화면 생성 전후의 모집단 보존을 검증한다.

즉, **서비스 화면의 전체 발전소 현황 = 예측 가능한 발전소 목록이 아니다.**

이 화면은 전국 설비 현황을 보여주는 기능이며, 모델이 어떤 발전소를 학습했는지를 나타내는 화면이 아니다.

## 3. Population B — AI 모델 학습·검증·테스트 모집단

### 목적

XGBoost, CNN-BiLSTM 및 Hybrid 비교 실험의 학습·검증·선택·최종 평가에 사용한다.

### 원칙

AI 모델은 전체 데이터를 무조건 사용하는 대신, **예측 실험에 적합한 발전소와 시간 행만 단계적으로 선별**한다.

선별 과정에서 확인하는 항목은 다음과 같다.

- 태양광 여부 (`energy_source=solar`)
- 발전량 타깃의 시간 해상도 적격성
- 공식 발전소 식별자와 provenance
- 기상관측소 매핑 근거
- 발전량-기상 시간키 overlap
- 시간 연속성
- 입력 피처 가용성
- Train/Validation/Calibration/Test 분할 후 유효 표본 수
- purge 및 lookback/horizon 적용 후 실제 학습 가능한 forecast sample 수
- 데이터 누수 여부

원본·Silver·Gold에서 제거하지 않고도 `quality_train_eligible`, registry/admission, training eligibility 상태를 통해 학습 포함 여부를 별도로 관리한다.

### 과거 구현에서 복원한 발전소 선별 기준

과거 실제 전처리 노트북의 3-way 분할은 다음과 같았다.

- Train: 2021-12-31 23:59:59까지
- Validation: 2022-01-01 00:00:00 ~ 2023-12-31 23:59:59
- Test: 2024-01-01 00:00:00부터
- split boundary purge: 24시간

발전소 단위로는 다음 조건을 적용했다.

1. Train / Validation / Test 세 구간에 모두 존재해야 한다.
2. 어느 구간이든 발전소 시계열에 1시간 초과 gap이 있으면 제외한다.
3. `validation_count <= train_count`여야 한다.
4. `test_count <= train_count`여야 한다.

실제 `excluded_bad_plants.csv`에는 이 비교 규칙으로 제외된 발전소의 Train/Validation/Test 행 수가 남아 있다.

현재 확인 가능한 버전관리 코드·PPT·README에서는 **각 split에 대해 고정된 최소 N건 숫자를 별도 하드코딩한 근거는 찾지 못했다.** 따라서 근거 없는 최소 건수를 임의로 추가하지 않는다.

### 현재 실험 분할

현재 최적화 실험은 모델 선택과 Hybrid gate 학습이 Test에 침범하지 않도록 Calibration을 별도로 분리한다.

- Train 60%
- Validation 15%
- Calibration 10%
- Test 15%
- purge gap 168시간

과거 3-way calendar split과 현재 4-way fraction split은 서로 다른 실험 계약이므로 포트폴리오에서 혼용하지 않는다.

## 4. 데이터가 줄어드는 것은 손실이 아니라 모델링 의사결정이다

포트폴리오에서는 `전체 데이터 -> 일부만 학습`을 단순한 데이터 삭제로 설명하지 않는다.

정확한 설명은 다음과 같다.

```text
공식 공개 전체 데이터
    |
    +--> 서비스/전국 현황 모집단
    |      - 원본 범위 유지
    |      - 검색/지도/지역 통계
    |      - 학습 제외 발전소도 계속 표시
    |
    +--> 모델링 후보 모집단
           - 발전원/식별/provenance 확인
           - 기상 매핑 및 시간키 결합
           - 품질 및 시간 해상도 검사
           - 연속성/분할/purge/lookback/horizon 검사
           - 최종 AI 학습·검증·테스트 모집단
```

따라서 모델 적격 데이터가 줄어들어도 **원본 및 서비스 현황 데이터는 그대로 보존**된다.

## 5. 포트폴리오에서 강조할 설계 의도

이 분리는 다음 역량을 보여주는 근거로 사용한다.

### 데이터 엔지니어링

- Bronze/Silver/Gold와 모델 적격성 상태를 분리했다.
- 원본 보존과 학습용 정제를 별개의 책임으로 설계했다.
- 데이터가 제외될 때도 provenance와 제외 사유를 남겨 재현성을 확보했다.

### 머신러닝 실험 설계

- 모델 성능을 높이기 위해 임의로 좋은 발전소만 고른 것이 아니라 사전에 정의한 데이터 적격성·시간 분할 규칙으로 모집단을 고정한다.
- Validation/Calibration/Test 역할을 분리해 모델 선택으로 인한 Test 오염을 방지한다.
- 발전소별 데이터 기간 차이와 시계열 gap을 명시적으로 관리한다.

### 서비스 설계

- 사용자에게 필요한 `전국 발전소 현황`과 AI가 실제 예측 가능한 범위를 혼동하지 않는다.
- 모델이 학습하지 못한 발전소도 서비스 현황에서 사라지지 않는다.
- 모델 적용 가능 범위와 전체 데이터 범위를 화면/문서에서 별도로 표현할 수 있다.

## 6. 포트폴리오 표현 예시

> 전국 발전설비 현황과 AI 학습 모집단을 분리했습니다. 전국 현황 화면은 EPSIS 공개 원본의 등록 범위를 유지해 모델 적격성 때문에 발전소를 삭제하지 않았습니다. 반면 예측 모델에는 발전원, 시간 해상도, 기상 매핑, 시계열 연속성, temporal split 및 purge 조건을 통과한 데이터만 사용했습니다. 이를 통해 서비스 정보의 완전성과 머신러닝 실험의 재현성·공정성을 동시에 유지했습니다.

면접에서는 `왜 데이터를 버렸는가?`보다 다음과 같이 설명하는 것이 정확하다.

> 데이터를 버린 것이 아니라 원본/서비스 모집단은 보존하고, 예측 문제에 적합한 학습 모집단만 별도로 정의했습니다. 학습 제외는 원본 삭제가 아니라 모델 eligibility 상태입니다.

## 7. 관련 canonical 근거

- `config/national_solar_inventory.json`: 전국 현황 원천 계약
- `src/solar_forecast/reporting/national_solar_inventory.py`: 전국 현황 집계
- `docs/DATA_FORMAT_AND_DASHBOARD_AUDIT.md`: 전국 현황 화면과 모델 화면 역할 분리
- `config/training_admission.json`: 학습 적격 정책 및 과거 기준 복원
- `src/solar_forecast/evaluation/training_eligibility.py`: 발전소별 학습 적격성 평가
- `src/solar_forecast/evaluation/temporal_split.py`: 현재 시계열 분할
- `config/experiments/optimized.json`: 현재 모델 비교 실험 계약
- `docs/MODEL_PREPROCESSING_ROADMAP.md`: 발전량/기상 품질 및 모델 전처리 정책

이 문서는 모집단 분리의 설명용 canonical 문서다. 실제 숫자·현재 적격 발전소 수·행 수는 실행 시점의 manifest와 audit 산출물을 우선한다.
