## 2026-09-17 작업 환경 CPU 실행 중단 — 사용자 로컬 GPU 원칙 정정

본 학습을 사용자 로컬 GPU에서 수행한다는 기존 지시를 놓치고 코드 `73a8607`에서
ChatGPT 작업 환경의 CPU 본 학습을 시작한 오류가 있었습니다. 실행 ID는
`20260917_145234_725672`이며 CI는 호출하지 않았습니다. 사용자 정정 후 프로세스가
이미 없음을 확인했고, 남아 있던 `running` 기록을 `interrupted`로 정리했습니다.
실제 프로세스 종료 시점과 원인은 확인되지 않았습니다. 이 실행을 재개하거나 정식 결과로
채택하지 않으며 이후 본 학습은 사용자 Windows 로컬 GPU에서 수행합니다.

- 입력: 보완된 전처리 v2 Gold의 태양광 적격 566,540행·18개 발전소.
- 설정: `observed_calendar_candidate.json`의 1/24/72시간, 후보 18개, Optuna 최대 150회.
  실제 입력 위치만 실행용 사본에 적용했고 분할·탐색 예산은 유지했습니다.
- 환경: Python 3.12.14, Torch 2.14.0+cu130, XGBoost 3.4.1, Optuna 5.0.0.
  GPU가 없어 CPU로 실행하며 Torch 연산 스레드 4개·interop 1개입니다.
- 실행 전 실제 ML 통합 검사 54개와 subtest 31개, 실행 도구 단계 검사 8개가 통과했습니다.
- 최초 진행 확인: 1시간 XGBoost 두 특징 후보가 각각 Optuna 15회와 최종 학습을 완료했고,
  CNN 24시간 입력 후보가 실제 학습을 시작해 첫 epoch의 checkpoint를 저장했습니다.

**이 기록은 중단된 실행이며 최종 성능 검증 완료가 아닙니다.** 전체 실행 상태는
`artifacts/benchmarks/20260917_145234_725672/manifest.json`, 로그는
`artifacts/verification/full_training_20260917.log`에 보존합니다. 마지막 저장 checkpoint는
첫 CNN 탐색의 12/20 epoch이며 최종 모델이 아닙니다. 모델 비교·Hybrid 채택·화면 갱신을
완료하지 않았습니다. 실행 도구에는 CUDA가 없으면 본 학습 전에 중단하는 확인을 추가했으며
사용자 로컬 프로젝트 파일과 GPU 실행 상태는 이 작업 환경에서 직접 확인하지 못했습니다.

2026-09-09, 코드 `f228b57f9b7c209f2b7ab4adf8bd6ac0740ef76a`에서 실행했습니다. [CI 34295513571](https://github.com/conanbke-ai/ESG_Project1/actions/runs/34295513571)는 구조 검사, **285 tests / 63 subtests**, 실측 원본 재구축, 제한된 학습, 저장 모델 재검증, 대시보드 반영까지 통과했습니다. 경고 18개는 pandas/Optuna 등의 호환성·실험 기능 알림입니다.

## 입력과 분할

저장소에 보관된 공식 발전량 CSV와 ASOS 관측자료로 `prepare-data --no-collected-downloads`를 실행했습니다. API 키나 예보 자료는 사용하지 않았습니다. 생성 Gold는 613,340행/21개 발전소이며, 태양광 학습 적격은 566,540행/18개 발전소입니다. 이는 저장된 원본만 재구축한 결과로, Windows의 추가 collector 파일을 포함한 이전 Gold 행 수와 동일한 입력이 아닙니다.

학습 실험은 관측 충족률로 선정한 `ewp:광양항광양냉장태양광`의 2024년 자료를 사용했습니다. 발전소 선정에 모델 점수를 사용하지 않았습니다.

| 항목 | 범위 |
|---|---|
| 2024년 실측 | 8,784시간, 관측률 100% |
| 과거 입력 이력 | 2023-12-25부터 168시간 |
| 전체 실험 입력 | 8,952행 |
| 기본 기상 관측 충족률 | 약 99.966% |
| Train 종료 | 2024-08-04 18:00 |
| Validation | 2024-08-11 19:00 ~ 2024-09-29 17:00, 1,175행 |
| Hybrid 비중 학습 | 2024-10-06 18:00 ~ 2024-10-14 20:00, 195행 |
| 별도 선택 평가 | 2024-10-21 21:00 ~ 2024-11-06 00:00, 364행 |
| 최종 Test | 2024-11-13 01:00 ~ 2024-12-31 23:00, 1,175행 |

모든 모델은 같은 목표시각/시작시각/발전소의 행으로 평가했습니다. 1/24시간 모두 공통 평가 행 충족률은 100%였습니다. 대상은 각각 1시간 또는 24시간 뒤의 한 시간 발전량입니다. 누락 목표를 보간하지 않았습니다.

시작시각까지의 관측값이 해당 시각에 사용 가능하다고 가정한 과거 평가입니다. ASOS와 발전량 자료의 실제 발행 지연은 재현하지 않았으므로 실시간 운영 성능으로 해석하지 않습니다.

## 실제 탐색 범위

- XGBoost: 기간별 Optuna 2회, 최대 128 trees, depth 3/5와 learning rate 0.03/0.08의 제한된 후보.
- CNN-BiLSTM: 기간별 입력창 24/168시간 각각 Optuna 1회, 각각 3 epochs. Conv 16, LSTM hidden 32 등 작은 네트워크로 고정했습니다.
- 관측 기상·이력 특징 한 조합만 사용했습니다. 전체 특징 조합 탐색은 기본 `optimized.json`에 정의돼 있지만 이 실행에는 포함하지 않았습니다.
- CNN은 두 기간 모두 Validation에서 168시간 입력창을 선택했습니다. 이 결과만으로 장기 예측 특화나 모델 계열의 우위를 결론내리지 않습니다.

## Test 결과

MAE/RMSE 단위는 시간당 발전량 MWh입니다. R²는 음수도 그대로 기록했습니다.

| 예측 대상 | 모델 | MAE | RMSE | R² |
|---|---|---:|---:|---:|
| 1시간 후 | XGBoost | 0.016908 | 0.034669 | 0.903009 |
| 1시간 후 | CNN-BiLSTM | 0.136506 | 0.185686 | -1.782250 |
| 1시간 후 | Hybrid | 0.026507 | 0.045094 | 0.835915 |
| 1시간 후 | 직전 관측 유지 | 0.028160 | 0.050026 | 0.798059 |
| 24시간 후 | XGBoost | 0.021157 | 0.042075 | 0.857149 |
| 24시간 후 | CNN-BiLSTM | 0.068464 | 0.099869 | 0.195185 |
| 24시간 후 | Hybrid | 0.026485 | 0.052271 | 0.779524 |
| 24시간 후 | 직전 관측 유지 | 0.024500 | 0.055944 | 0.747453 |

1시간 과제는 선택 구간에서 XGBoost를 선택했고 Test에서도 XGBoost가 가장 낮은 MAE를 기록했습니다.

24시간 과제에서는 선택 구간 MAE가 XGBoost 0.035125, Hybrid 0.034591이어서 Hybrid를 선택했습니다. **최종 Test에서는 Hybrid의 MAE가 XGBoost보다 높았고 기준선에도 미치지 못했습니다. 개선이 재현되지 않았습니다.** Test를 보고 선택 기록을 변경하지 않았으며, 화면에서 검증 구간의 선택과 최종 Test 결과를 구분합니다. 이번 실험은 Hybrid의 최종 채택 타당성을 입증하지 못했습니다.

CNN의 이번 성능은 작은 네트워크·3 epochs라는 제한과 특정 발전소/계절 범위 아래의 결과입니다. 충분히 조정한 CNN의 한계나 기존 저장 CNN의 성능을 뜻하지 않습니다. 전체 실측 데이터에서 충분한 탐색 후 다시 검증하는 작업이 남아 있습니다. 이미 확인한 Test를 이후 튜닝에 사용한다면 최종 확증에는 새로운 미사용 구간이 필요합니다.

## 2026-09-16 후속 검수: 실행 환경과 재학습

위 표는 9월 9일 실행 기록으로 보존합니다. 이후 모델 소스와 실측 입력을 바꾸지 않은 [CI 35046242140](https://github.com/conanbke-ai/ESG_Project1/actions/runs/35046242140)와 [CI 35046632278](https://github.com/conanbke-ai/ESG_Project1/actions/runs/35046632278)에서는 다음 결과가 나왔습니다. 두 실행 모두 전체 테스트 285개와 하위 검사 63개, 실측 학습, 저장 모델 재예측을 통과했습니다.

| 예측 대상 | 선택 구간의 선택 | XGBoost Test MAE | CNN Test MAE | Hybrid Test MAE |
|---|---|---:|---:|---:|
| 1시간 후 | Hybrid | 0.016908 | 0.051547 | 0.021528 |
| 24시간 후 | Hybrid | 0.021157 | 0.065813 | 0.027445 |

단위는 MWh입니다. 이번 두 실행의 점수는 서로 동일하며, 선택된 CNN의 모델 파일·전처리·예측 CSV SHA도 일치했습니다. 1시간 CNN은 24시간 입력창을 선택했습니다. 두 기간 모두 선택 구간에서 Hybrid를 골랐지만 Test에서 최선 단일 모델보다 나빴습니다. Hybrid의 일반화 개선을 입증하지 못했다는 판단은 유지합니다.

반면 **9월 9일과 9월 16일 사이에는 CNN 재학습 결과가 달랐습니다.** 모델 소스 SHA, 입력 CSV SHA, 네 후보의 CNN 설정·특징 순서·전처리값·분할·학습 배치 횟수는 같았습니다. XGBoost 점수는 같았고, 두 실행 모두 저장 모델 재예측은 통과했습니다. 따라서 저장 모델 재예측 성공만으로 서로 다른 실행 환경의 재학습 결과까지 같다고 결론낼 수 없습니다.

확인된 환경 차이에는 scikit-learn 1.9.0→1.9.1, threadpoolctl 3.6.0→3.7.0 등이 있습니다. 당시 CPU 종류와 Torch 연산 backend 설정은 기록되지 않아 **정확한 원인을 특정하지 못했습니다.** 패키지 차이를 직접 원인으로 단정하지 않습니다. PyTorch도 버전·플랫폼을 바꾼 결과의 완전한 재현을 보장하지 않습니다([공식 재현성 문서](https://docs.pytorch.org/docs/stable/notes/randomness.html)).

후속 검증에는 다음을 추가했습니다.

- `config/environments/benchmark_cpu_py311.constraints.txt`: 확인한 CPU 환경의 패키지 54개 버전 고정. CI는 Python 3.11.16과 Ubuntu 24.04를 사용합니다.
- 실측 실행 보고서에 CPU 모델·ISA, Torch 빌드·스레드·backend 설정 기록.
- `tools/verify_benchmark_retraining.py`: 같은 입력으로 체크포인트·Optuna DB를 새로 만들어 다시 학습하고, 모든 후보의 Validation/Calibration/Test 예측 및 최종 선택을 비교. 허용오차는 10⁻⁶ MWh입니다.

이 검사는 기록된 같은 환경 안에서의 재학습 재현성을 확인합니다. 다른 CPU에서도 항상 같은 결과가 나온다는 보장이나 새로운 미사용 Test 평가를 대신하지 않습니다. 9월 16일 원본 산출물은 [CI artifact](https://github.com/conanbke-ai/ESG_Project1/actions/runs/35046632278/artifacts/10426593685)에 있으며, ZIP SHA256은 `542a357ea18b6cec5e37ae39cc10c99d1f210a472a8a29201a1f249d4a9b907d`입니다.
